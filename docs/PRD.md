# 커피 주문 앱
## 1. 프로젝트 개요
### 1.1 프로젝트명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능


## 2. 기술 스택
- 프런트 엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본사항
- 프런트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용
- 학습 목적이므로 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 주문하기 화면 PRD
### 4.1 목적 및 사용자
- 목적: 사용자가 커피 메뉴와 옵션을 선택해 장바구니에 담고, 주문을 제출할 수 있게 한다.
- 사용자: 인증 없이 주문하는 일반 사용자
- 이번 문서의 범위: 주문하기 화면의 메뉴 탐색, 옵션 선택, 장바구니 확인 및 주문 제출
- 관리자 화면의 재고·주문 관리 상세 요구사항은 이 범위에 포함하지 않는다.

### 4.2 화면 구성
1. **상단 내비게이션**
   - 브랜드명 `COZY`를 표시한다.
   - `주문하기`와 `관리자` 메뉴를 제공한다.
   - `주문하기` 화면에서는 현재 메뉴가 선택된 상태로 표시된다.
   - `관리자`를 선택하면 관리자 화면으로 이동한다.
2. **메뉴 목록**
   - 주문 가능한 커피를 카드 형태로 표시한다.
   - 각 카드에는 메뉴 이미지, 이름, 기본 가격, 간단한 설명, 추가 옵션 및 `담기` 버튼을 표시한다.
   - 와이어프레임 예시 메뉴: 아메리카노(ICE) 4,000원, 아메리카노(HOT) 4,000원, 카페라떼 5,000원.
   - 와이어프레임의 옵션 예시: 샷 추가(+500원), 시럽 추가(+0원). 메뉴별 제공 옵션은 메뉴 데이터에 따른다.
3. **장바구니**
   - 메뉴 목록 아래에 장바구니를 표시한다.
   - 담긴 메뉴의 이름, 선택 옵션(있는 경우), 수량, 항목별 금액과 전체 주문 금액을 표시한다.
   - 장바구니가 비어 있으면 비어 있음을 알리고, 주문 제출은 할 수 없게 한다.
   - `주문하기` 버튼으로 장바구니의 주문을 제출한다.

### 4.3 기능 요구사항
#### 메뉴 및 옵션
- 메뉴 목록은 백엔드에서 제공하는 메뉴 데이터를 기준으로 표시한다.
- 메뉴별 이름, 설명, 기본 가격, 이미지 및 선택 가능한 옵션을 표시한다.
- 사용자는 메뉴를 장바구니에 담기 전에 카드의 옵션을 선택할 수 있다.
- 옵션의 추가 금액을 메뉴 가격에 반영한다. 추가 금액이 0원인 옵션도 선택 내역에 포함한다.
- 메뉴 목록을 불러오지 못하면 오류 안내를 표시하고, 사용자가 다시 시도할 수 있도록 한다.

#### 장바구니 및 금액
- `담기`를 누르면 현재 선택한 옵션을 포함한 메뉴가 장바구니에 추가된다.
- 항목 금액은 `(기본 가격 + 선택 옵션 추가 금액) × 수량`으로 계산하며, 전체 금액은 항목 금액의 합으로 계산한다.
- 수량이 여러 개인 항목은 수량과 항목 금액을 함께 표시한다.
- 와이어프레임 예시 계산은 아메리카노(ICE) 1개(샷 추가) 4,500원과 아메리카노(HOT) 2개 8,000원, 총 12,500원이다.
- 표시 금액은 원화와 천 단위 구분 기호를 사용한다.

#### 주문 제출
- 장바구니가 비어 있으면 주문 제출을 막는다.
- 제출 중에는 중복 제출을 방지하고 진행 상태를 사용자에게 표시한다.
- 주문이 성공적으로 저장되면 주문 완료 안내를 표시한다.
- 주문 저장에 실패하면 장바구니를 유지하고 오류 안내와 재시도 방법을 제공한다.
- 결제 기능은 제공하지 않는다.

### 4.4 사용자 흐름
1. 사용자가 메뉴와 가격을 확인한다.
2. 원하는 메뉴의 옵션을 선택하고 `담기`를 누른다.
3. 장바구니에서 담긴 메뉴, 옵션, 수량 및 합계를 확인한다.
4. `주문하기`를 눌러 주문을 제출한다.
5. 저장 결과에 따라 완료 안내 또는 오류 안내를 확인한다.

### 4.5 수용 기준
- 메뉴 카드에 이름, 기본 가격, 설명, 제공 옵션 및 담기 버튼이 표시된다.
- 선택한 옵션과 추가 금액이 장바구니 항목 및 합계에 정확히 반영된다.
- 여러 메뉴와 수량의 항목 금액·전체 금액이 정확히 계산된다.
- 와이어프레임 예시 구성에서 전체 금액이 12,500원으로 표시된다.
- 비어 있는 장바구니는 제출할 수 없고, 주문 요청이 진행 중일 때 중복 요청이 발생하지 않는다.
- 주문 성공 및 실패 상황이 사용자에게 구분되어 안내되며, 실패 시 장바구니 내용이 보존된다.

### 4.6 와이어프레임에서 확정되지 않은 항목
- 메뉴별 실제 이미지·설명·목록과 옵션 구성 및 가격은 운영 데이터로 확정한다.
- 장바구니에서 수량 변경·항목 삭제를 제공할지, 동일 메뉴와 옵션을 한 줄로 합칠지는 별도 결정이 필요하다.
- 주문 제출 후 장바구니 초기화 여부와 완료 화면의 구체적인 내용은 별도 결정이 필요하다.
- 품절 메뉴의 노출·담기 제한 및 주문 제출 시 재고 확인 규칙은 관리자 재고 기능과 함께 정의한다.
- 모바일 화면의 카드 배치와 반응형 기준은 별도 UI 설계에서 확정한다.

## 5. 관리자 화면 PRD
### 5.1 목적 및 사용자
- 목적: 관리자가 주문 처리 현황을 확인하고 커피 메뉴별 재고를 조정할 수 있게 한다.
- 사용자: 매장 관리자
- 이번 문서의 범위: 관리자 대시보드, 재고 수량 조정, 주문 현황 확인 및 주문 상태 처리
- 메뉴 등록·수정, 가격 및 옵션 관리 기능은 와이어프레임에 없으므로 범위에 포함하지 않는다.

### 5.2 화면 구성
1. **상단 내비게이션**
   - 브랜드명 `COZY`와 `주문하기`, `관리자` 메뉴를 표시한다.
   - 관리자 화면에서는 `관리자` 메뉴가 현재 선택된 상태로 표시된다.
   - `주문하기`를 선택하면 주문하기 화면으로 이동한다.
2. **관리자 대시보드**
   - 총 주문 수와 상태별 주문 수를 표시한다.
   - 와이어프레임은 총 주문, 주문 접수, 제조 중, 제조 완료 건수를 예시로 보여준다.
3. **재고 현황**
   - 메뉴별 이름과 현재 재고 수량을 카드 형태로 표시한다.
   - 각 카드에 수량을 1개씩 늘리는 `+`와 줄이는 `-` 조작을 제공한다.
   - 와이어프레임 예시 메뉴는 아메리카노(ICE), 아메리카노(HOT), 카페라떼이다.
4. **주문 현황**
   - 주문 시각, 주문 메뉴 및 수량, 주문 금액, 처리 액션을 표시한다.
   - 와이어프레임 예시 행에는 주문 접수 액션 버튼이 표시된다.

### 5.3 기능 요구사항
#### 대시보드
- 대시보드 수치는 저장된 주문 데이터를 기준으로 표시한다.
- 총 주문 수와 상태별 주문 수는 최신 데이터와 일치해야 한다.
- 수치를 불러오지 못한 경우 오류 안내를 표시하고 다시 시도할 수 있게 한다.

#### 재고 관리
- 메뉴별 현재 재고 수량을 백엔드에서 조회해 표시한다.
- `+`를 누르면 해당 메뉴 재고를 1개 증가시키고, `-`를 누르면 1개 감소시킨다.
- 재고는 0개 미만이 될 수 없으며, 0개에서 감소 조작은 비활성화하거나 사용자에게 불가 사유를 안내한다.
- 수량 변경이 저장되는 동안 해당 조작의 중복 요청을 방지하고 진행 상태를 표시한다.
- 저장 성공 시 최신 수량을 표시하고, 실패 시 오류를 안내하며 성공한 것처럼 화면만 갱신하지 않는다.

#### 주문 현황 및 상태 처리
- 주문별 시각, 메뉴명, 수량, 주문 금액과 현재 처리 상태를 표시한다.
- `주문 접수` 액션을 제공하여 새 주문을 관리자가 처리할 수 있게 한다.
- 주문 상태 변경은 백엔드에 저장하고, 성공 후 목록과 대시보드 집계에 반영한다.
- 상태 변경에 실패하면 기존 상태를 유지하고 오류 안내 및 재시도 방법을 제공한다.
- 이미 처리 중인 변경의 중복 제출을 방지한다.

### 5.4 사용자 흐름
1. 관리자가 관리자 화면에 진입해 주문 건수와 메뉴별 재고를 확인한다.
2. 필요한 경우 메뉴 카드의 `+` 또는 `-`로 재고 수량을 조정한다.
3. 주문 현황에서 주문 시각, 메뉴, 수량 및 금액을 확인한다.
4. 주문의 처리 액션을 눌러 주문 상태를 갱신한다.
5. 저장 결과가 재고, 주문 목록 및 대시보드에 반영됐는지 확인한다.

### 5.5 수용 기준
- 대시보드에 총 주문 및 상태별 주문 수가 표시되고 저장 데이터와 일치한다.
- 각 메뉴의 현재 재고 수량이 표시되며 `+`와 `-` 조작으로 1개씩 변경할 수 있다.
- 재고는 음수가 되지 않으며, 변경 성공 전에는 새 수량으로 확정 표시하지 않는다.
- 주문 목록의 각 행에 주문 시각, 메뉴와 수량, 금액 및 처리 액션이 표시된다.
- 주문 상태 변경 성공 시 해당 주문 상태와 대시보드 집계가 함께 갱신된다.
- 조회 및 변경 실패 시 사용자에게 오류가 안내되고, 실패한 변경이 성공한 것처럼 표시되지 않는다.

### 5.6 와이어프레임에서 확정되지 않은 항목
- `주문 접수` 버튼이 주문을 접수 대기에서 접수 상태로 바꾸는지, 접수된 주문을 다음 제조 단계로 보내는지 상태 전이를 확정해야 한다.
- 주문 상태의 전체 단계, 상태별 대시보드 집계 정의, 취소 주문 처리 방식은 별도 정의가 필요하다.
- 주문 현황의 정렬 순서, 표시 건수, 과거 주문 조회 및 새 주문 자동 갱신 방식은 별도 결정이 필요하다.
- 재고가 주문 접수·제조 완료 중 어느 시점에 차감되는지, 옵션별 재고를 관리하는지는 주문·재고 정책에서 확정한다.
- 재고 변경에 최대 수량을 둘지, 관리자가 수량을 직접 입력하는 기능을 제공할지는 별도 결정이 필요하다.
- 현 PRD의 기본사항에 따라 인증은 범위에서 제외되어 있으나, 관리자 접근 제한 방식은 배포 전 별도로 검토해야 한다.
- 모바일 화면의 배치와 반응형 기준은 별도 UI 설계에서 확정한다.
